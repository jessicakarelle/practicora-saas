# Internationalisation

Practicora sépare les traductions du code afin d’éviter d’écrire les textes visibles directement dans les composants.

## Structure

Les fichiers sources se trouvent ici :

```text
src/i18n/locales/<locale>/<domaine>/<namespace>.json
```

Domaines utilisés :

- `app`;
- `auth`;
- `billing`;
- `common`;
- `content`;
- `marketing`;
- `organization`;
- `platform`.

Exemple :

```text
src/i18n/locales/fr/platform/users.json
src/i18n/locales/en/platform/users.json
```

## Générer les catalogues

```powershell
npm.cmd run i18n:generate
```

Le script lit les fichiers JSON, vérifie la structure des langues principales et génère les catalogues utilisés par l’application dans :

```text
src/i18n/generated/
```

Les fichiers générés ne doivent pas être modifiés manuellement.

## Vérifier les traductions utilisées dans le code

```powershell
npm.cmd run i18n:check
```

Cette vérification recherche notamment des textes visibles qui auraient été écrits directement dans les fichiers TypeScript/TSX.

Des éléments purement techniques peuvent rester dans le code, par exemple une route, une clé interne ou une valeur de base de données. Les textes destinés à l’utilisateur doivent passer par les fichiers de locale.

## Ajouter une nouvelle clé

1. choisir le bon domaine et le bon namespace;
2. ajouter la clé dans les fichiers de langue concernés;
3. utiliser la clé depuis le composant;
4. lancer `npm.cmd run i18n:generate`;
5. lancer `npm.cmd run i18n:check`.

Exemple d’utilisation :

```text
translate(locale, "domaine.namespace.cle")
```

## Langues actuelles

```text
fr | en | es | pt | de | it | ar
```

Le français et l’anglais servent de références principales. Les autres langues doivent encore être relues attentivement avant d’être considérées comme des traductions finales.
